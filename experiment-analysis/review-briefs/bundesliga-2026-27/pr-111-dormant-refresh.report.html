How the dormant path is designed to work

One observation, eight independent community heads

C3 supplies the common descriptor, immutable bundle, handoff, receipts, health reduction, and publication reconstruction. E1 supplies Club Elo HTTP acquisition, inert parsing, exact mapping, source evaluation, and command consumption. This diagram describes the source-enabled contract; the flags remain off.

  1. Freeze retained evidence

    Verify each expected community’s freshest seed/LKG before source evaluation. Missing heads may use valid seed; corrupt heads fail.

  2. Acquire and evaluate · E1

    Bound the HTTP response and parse it without executing scripts. Validate its own displayed date, exact club identities, integer values, and complete 18-club coverage.

  3. Seal and hand off · C3

    Record one canonical observation. Only an eligible candidate carries the hashed payload club-elo/source.html in the immutable bundle.

  4. Consume per community

    E1 rechecks that lane’s retained selection, then uses guarded publication. C3 completes the canonical receipt and the post-commit issue-projection seam.

Independent progress: shared NotNewer is valid only when the candidate is no newer than every retained selection. If one community lags, the payload stays eligible so that community can advance. Other heads can retain their own verified state.

A head points to the selected complete document set. A receipt records a community’s outcome for the observation. Immutable payload hashes bind publication metadata to source evidence; snapshot identity remains based on document bytes. See ADR-0081.

Reviewer checklist and residual risks

  • Confirm the merge boundary. Both source flags remain false; no W1/A1 release or production routing change is hidden in the diff.
  • Follow one candidate end to end. Check exact mapping and date evidence, immutable HTML payload identity, lane selection, guarded publication, and persisted receipt completion.
  • Review the difficult retained-state cases. Lagging communities must not be suppressed by shared NotNewer; corrupt LKG must fail; replay must not manufacture a new publication or mutate history.
  • Preserve schema-family compatibility. Historical fractional CSV evidence and strict integer HTML are intentionally different. Unknown/mixed publication shapes fail.
  • Keep source drift visible. Strict HTML parsing can reject future upstream changes. Fixture coverage is not live-source acceptance; fallback retains truthful dates rather than claiming freshness.
  • Keep roster deferral explicit. No authoritative sidecar, no R1 acceptance or automatic roster freshness. The rejected DuckDB/current-source evidence cannot take over from seed/LKG.
  • Check the current head. Match required green checks to the commit being merged. The runs above establish the prior baseline only. Concurrent or contradictory publication state requires manual recovery under the accepted contract.
